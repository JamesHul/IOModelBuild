# Australian Input-Output impact model

Read this before touching anything. It carries decisions that took a lot of work to establish and that are easy to get wrong.

## What this project is

A generic, reusable Excel model that takes a spending shock at purchasers' prices, strips it to domestic basic prices using ABS data, and applies a **supplied** multiplier set to produce direct, indirect, induced and total impacts on output, wages, value added and employment.

The model is **generated by script**, not hand-built. `scripts/build_model.py` writes the whole workbook. Never hand-edit the output workbook — change the script and regenerate. A hand-edit cannot be reproduced when the next ABS vintage lands.

## Non-negotiable rules

1. **RAW tabs hold source data verbatim.** Whatever came from the ABS or from the multiplier provider goes in unchanged: every column including the Total columns, every row including re-exports and the primary-input rows, `n.a.` text left as text. No trimming, no expanding, no re-spining, no blanking.
2. **All transformation happens in a `MAP_` layer of visible formulas.** Spine mapping, the 6700 bridge, `n.a.` handling, column-group aggregation — each is a formula someone can click into and audit.
3. **Multipliers are an input, never derived.** The model does not compute a Leontief inverse. It reads the supplied set.
4. **No hardcoded results anywhere downstream of RAW.** Every number in the calculation chain is a formula.
5. **Never fill a missing region with another region's data.** Leave it empty so the QA gate blocks the run. Silent placeholders that look like data are the worst failure mode this model has.

## Domain facts that are easy to get wrong

- **ABS Table 5 and Table 8 are both industry-by-industry at basic prices.** Neither is at purchasers' prices. The difference is import allocation: Table 5 is *direct allocation* (intermediate quadrant is domestic only, imports shown as a separate primary input row); Table 8 is *indirect allocation* (imports embedded in the flows). **Domestic multipliers come from Table 5.** Building off Table 8 inflates everything.
- **Imports = Table 8 less Table 5, cell by cell.** This is why the model needs no ABS Table 2 or Table 3. Verified: column 0101, 29,020.2 + 4,525.9 = 33,546.1.
- **The ABS has not published IO multipliers since 1998-99** and does not publish state or territory IO tables at all. Any state table in this project is a derived product from a provider and its provenance must be documented.
- **IOIG(2022) has 115 industries, not 114.** The supplied multiplier set uses a 114-code spine: it has no `6700 Imputed rent for owner-occupiers` and treats ownership of dwellings as a single `6701`. That is the only spine difference.
- **The GFCF columns do not contain materials.** They hold finished capital assets — construction services, machinery, software. Nationally the whole General Government GFCF column shows $20m of iron and steel against $35,115m of civil construction. A bill of quantities must be allocated to the **Intermediate** column group (the contractor is a business buying inputs), not to GFCF. Putting materials in a GFCF column produces zero and silently drops the line.
- **GVA has three definitions.** Factor cost = P1+P2. **Basic prices = P1+P2+P4** — this is the ABS "Value Added" row and the headline. Market prices = P1+P2+P3+P4. Do not include P3 (taxes on products) in headline GVA.
- **Total output for the denominator is intermediate use plus ALL primary input rows.** The supplied state blocks use P3a/P3b/P3c/P3d and P4a/P4b where the national block uses P3/P4. Sum the P-rows dynamically or you will understate output and inflate every derived multiplier.
- **Margin control total.** ABS Tables 23-34 for 2023-24 sum to $422,034m including the re-exports row, $421,410m on the 115-code spine. Wholesale $182,778m and retail $146,374m on the spine. Use these as gates.
- **The 2024-25 ABS release (due March 2027) changes the transport margin treatment** from SNA1968 to SNA2008. The adjustment is worth $46.8bn in 2023-24. Expect a genuine series break; never hardcode a margin rate.
- **Retail margin is overwhelmingly a household phenomenon** — about $140bn against Q1 versus under $7bn across all 115 industry columns combined. Strip using the column the buyer actually sits in.

## Known state of the code

`scripts/build_model.py` is the working v0.2 generator, proven: 25 tabs, 28,406 formulas, recalculates with zero errors. It does **not** yet comply with rules 1 and 2 above. Four things it does that must be fixed when the real data is loaded:

1. Drops the `Total Industry Uses`, `Final Uses (Q1 to Q7)` and `Total Supply` columns from the ABS tabs.
2. Drops the `Re-exports` row from the margin tables, and the primary-input rows (T1, P1-P6, Australian Production, Value Added) from Table 5 and Table 8. Those primary-input rows are exactly what the multiplier reconciliation check needs.
3. Expands the 114-code state block onto the 115 spine inside the RAW writer, inserting a zero row and column for 6700.
4. Writes `n.a.` cells in the multiplier set as blanks (4,284 of them) and populates 6700 by duplicating 6701.

The fix: RAW writers take the source block whole; a new `MAP_Spine`, `MAP_Multipliers` and `MAP_StripData` layer does the reshaping in formulas.

## Working conventions

- Codes are **text**, always. `0101` as a number becomes `101` and breaks every lookup.
- Lookups are `INDEX`/`MATCH` on the code. No `VLOOKUP` on position, no `OFFSET`, no `INDIRECT`.
- Colour key in the workbook: blue text = hardcoded input, black = formula, green = cross-sheet link, yellow fill = the analyst must complete it.
- After every build, recalculate and scan for errors before declaring success. Install the xlsx skill for this: `/plugin marketplace add anthropics/skills` then `/plugin install document-skills@anthropic-agent-skills`. It carries a `recalc.py` that opens the file headless, forces a full recalculation and reports every error cell. **A build that has not been recalculated is not verified.**
- Excel is the target environment. If LibreOffice and Excel disagree, Excel wins.
- Commit the script and the generated workbook together so the workbook can always be traced to the code that made it.

## Verification habits that have caught real bugs

- **Reconcile the supplied multipliers against the supplied Table 5.** Derive the simple output multiplier from the flow table and compare. On the V2 drop all nine regions match 114/114 within 0.001; against Table 8 they do not match at all. `scripts/check_sources.py` does this. Run it on every new data drop. Two things it must get right, both of which have already produced a `nan`: index off the block's own position (`verbatim[0]` **is** source row 13, so a src_row is not an index), and take the denominator from the `Production` row rather than `T1`.
- **Empty string is not a mismatch.** `openpyxl` writes `''` back as an empty cell, which made a verbatim round-trip report 1,244 phantom differences. Collapse `None` and `''` before comparing — but only those. A `0`, a `'0'` or an `'n.a.'` is real content.
- **Test region distinctness.** In the master model, six of eight state flow-table blocks were byte-identical to NSW, and five of eight multiplier sets were byte-identical to Australia. Nothing in the workbook would have revealed that.
- **State multipliers must be strictly smaller than national.** Smaller economies leak more. Enforced as a warning that names the offending industries, not a hard fail: a wholesale regionalisation failure shows up as *most* industries above national or as an identical block, and the distinctness and reconciliation gates already catch those. A named handful is a question for the provider.
- **Watch int vs float when reading results back.** Twice now a verification script has reported a false discrepancy because `isinstance(x, float)` skipped values Excel stored as integers. Use `numbers.Number`.
- **Check operator precedence in generated formulas.** `=IFERROR(A-B-C/D,"")` divides only `C`. Wrap numerators in parentheses.

## The ABS margin and tax data as loaded

`data/abs/`, fourteen files, ABS 5209.0.55.001 **2023-24** release (25 March 2026). Tables 23-34 (margins), Table 35 (net taxes) and Table 21 (the control).

- **All thirteen cubes share one grid**: r1 column codes from col C, r2 title in col B, r4-118 the full **115-code spine**, **r119 Re-exports**, r121 Total. Columns: C-DM the 115 industry columns, DN Total Industry Uses, DO-DU Q1-Q7, DV Final Uses, DW Total Supply.
- **Row codes are stored as numbers**, so `0101` arrives as `101`. `norm_code` zfills them. This is the leading-zero trap, live in the real files.
- **Every control total matches to the dollar**: the twelve margins individually, $421,410m on the spine, $422,034m including re-exports, net taxes $168,673m. Re-exports are $585m wholesale and $39m port handling, $624m in total.
- **Table 21 is the independent cross-check** and agrees exactly. Its columns are A code, B name, **C Margin Commodity**, D Non margin, E Total — column E is roughly double and is not the comparable figure.
- Table 21 also confirms the earning-industry map: 4801 = 2,512 = pipeline 2,392 + water 120; 5201 = 1,096 = port handling 1,057 + 39 re-exports.
- **ABS Table 5 and Table 8 are not needed and are not loaded.** The flow tables come from the provider's regionalised set and imports are derived from it.

## The supplied data as loaded (V2 drop)

`data/supplied/Piggy IO tables and multipliers_V2.xlsx`, 27 data sheets: Table 5, Table 8 and a multiplier summary for each of Aus, NSW, Vic, Qld, SA, WA, Tas, NT, ACT. Loaded by `scripts/load_sources.py`, stacked into `output/IO_RAW_Stacked.xlsx` by `scripts/build_raw_stacked.py`, proven verbatim by `scripts/verify_stacked.py` (574,857 cells, 0 mismatches).

- **Vintage is 2022-23**, not the 2021-22 of the old master. Every sheet says `$m 2022-23`.
- **Every sheet shares one grid**, which is what makes stacking safe: r10 column codes, r11 region name in col B, r13 first data row, col A code, col B label, col C+ matrix. Rows 13-136 are 114 real codes plus 10 `Dummy` rows (9901-9910).

- **Both national and state blocks now use P3a/P3b/P3c/P3d and P4a/P4b.** The old note that only state blocks split them no longer holds for this vintage.
- **The multiplier set has 15 measure blocks of 11 effects**, 12 columns apart from col C. Three are the GVA definitions: `Value added at factor cost`, `Value added` and `Value added at market prices`. **`Value added` is the basic-prices block and the headline.** Do not reach for the market-prices one.
- **Employment is FTE** — `Employment (FTE)`, col EH of each *state* Table 5. There is no employment column on Aus Table 5.
- 996 `n.a.` text cells per region (1,140 for ACT). Kept as text in RAW.
- All nine regions verified distinct across T5, T8 and multipliers — no repeat of the master model's copies.
- Reconciliation passes 114/114 within 0.001 in **all nine** regions, max deviation 0.0000.
